# Bug backlog

Updated: 2026-10-23

## Open

- **Q-1003 quotation shows inconsistent quantity, price, line total, and subtotal.** The reported preview figures cannot all be produced by the current single render/calculation path. The saved IndexedDB record has not been inspected, and no quotation data has been changed. Keep Q-1003 untouched until its raw `items[].qty` and `items[].price` values are reviewed read-only; then determine whether the defect is stored data or stale/mixed runtime output.
- **Quotation display does not validate stored numeric fields before calculating.** `js/quotes.js` calculates directly from saved `qty` and `price`; `js/pdf.js` also renders those values directly. Add safe read-time validation in the later regression/fix pass, without silently rewriting existing quotes.
- **Project calculator requires manual regression review on iOS Safari.** Verify catalog CRUD, project save/reopen/delete, fractional cable quantities, missing-cost/profit messaging, tax/discount boundaries, IndexedDB upgrade from database version 1, offline cache update, and quote handoff before release.
- **Customer, quotation, and project links require browser regression.** Verify customer-linked quote filtering, project customer selection, project-to-quotation links/handoff, deleted/renamed customer behavior, and quote snapshot behavior when the master customer or catalog changes. No saved records were read or modified during this implementation.
- **Dashboard and backup export require browser regression.** Confirm displayed counts after CRUD changes and export download/failure behavior in supported browsers; no actual browser or IndexedDB was used for these checks.
- **Backup import/restore is not implemented.** A version-4 local JSON export covers settings, clients, quotes, pricebook, projects, accounts, transactions, categories, suppliers, payables, and receivables using one readonly IndexedDB transaction. Import remains pending until schema validation, conflict preview, and non-destructive transaction behavior are designed. No backup has been imported, and browser storage has not been inspected.
- **Accounting module needs browser regression.** Verify version-3-to-4 IndexedDB upgrade preserves all existing stores and records; test account and supplier workflows, category management, partial/full and rejected overpayment settlements, same-currency enforcement, accounting totals, filters, error visibility, and version-4 backup export. No real browser database was opened or migrated during this implementation.
- **Financial reports need browser and historic-data regression.** New period reports and customer/supplier statements calculate from linked receivable/payable documents and settlement transactions; verify partial settlements, dates on period boundaries, multiple currencies, and legacy documents whose `settledAmount` differs from the linked settlement sum. The source warns on statement discrepancies, but no real records have been read.
- **Project summaries are intentionally partial.** They include only receipts, payments, payables, and receivables linked by `projectId`; unrelated account movements cannot safely be attributed. Linked quote and project amounts are labeled as estimates/customer quote values, never actual income. Verify presentation with projects containing both linked and unlinked activity.
- **Accounting reports skip malformed movements.** The calculation reports an invalid-movement count and excludes records with invalid dates, amounts, account links, currencies, or account opening-date violations. There is not yet a dedicated repair/export tool for such records; verify this warning is understandable and that malformed legacy rows remain editable.
- **Later accounting stages remain pending.** Technician payroll, inventory, advanced tax accounting, tax invoices, and backup restore remain out of scope.

## Resolved in this development increment

- Added a local CCTV project estimate workflow with editable BOM, project price overrides, material cost visibility, labor, discount, and configured optional tax.
- Added explicit meter-based cable entry guidance; cable lengths are not inferred from camera counts.
- Added local product catalog and saved project estimates. Catalog changes do not mutate project or quote snapshots.
- Added handoff into the existing quotation editor; the existing quotation and PDF layout are reused.
- Blank internal costs remain unknown. The calculator reports partial cost coverage and withholds profit until all material costs and any charged labor cost are known; an explicit zero is still accepted.
- Added PoE and network equipment categories. No HDD capacity, power sizing, or cable-length estimates were fabricated.
- Fixed a calculator defect found during this pass: item loading attempted to read a nonexistent `data-field="id"`, which prevented BOM totals from being calculated. The catalog ID now comes from the row snapshot metadata.
- Blank unit prices/quantities remain invalid; unknown internal costs remain explicitly unknown rather than being treated as zero. Profit is withheld until costs needed for the calculation are known.
- Catalog CRUD validates required name/category/unit/selling price and optional internal cost; blank cost means unknown while numeric zero means known zero. Deletion requires confirmation, and saved project/quotation lines retain their own snapshots.
- Added a local-only versioned export of all supported stores. Restore is deliberately pending; export includes private customer and internal cost data and is labeled accordingly.
- Static calculation and syntax checks were run for this increment; browser, iOS Safari, real IndexedDB migration, offline, and PDF visual checks remain unverified.
- Added an Arabic RTL dashboard with counts for saved customers, projects, and quotations only; it makes no revenue or profit claims.
- Added a foundational accounting view for cash/bank accounts, income and operating-expense categories, receipts, payments, owner withdrawals, and transfers. Date range, account, type, and category filters apply to the transaction history and actual period summary.
- Accounting balances are derived from account opening balances plus valid recorded movements dated on or after account opening. Receipts add to balances; payments and owner withdrawals subtract; transfers subtract from the source and add to the destination. Transfers are excluded from operating income/expenses; withdrawals are shown separately and do not reduce operating profit. Reports are grouped by currency with no implicit conversion. Estimates and quotes never create actual transactions.
- Added additive IndexedDB v3 stores `accounts` and `transactions` using `{id}` keys; database name `ain-db` and all existing stores/key paths remain unchanged. Account currency cannot be changed once movements exist; account opening date cannot move past saved movements; accounts with movements cannot be deleted and can be deactivated instead. Account balances are not cached, so editing/deleting a movement recalculates from source records.
- Updated the versioned local backup snapshot/export to schema version 2 and include accounting stores in the same read-only transaction. Restore remains disabled. No real IndexedDB data was inspected or modified.
- Added persistent income and operating-expense categories with Arabic defaults, category creation/rename/deactivation, same-type duplicate-name validation, and immutable type for categories referenced by saved activity. Deactivated categories remain attached to historical records and can be retained while editing an older transaction.
- Added supplier records with edit and deactivate workflows, and supplier payable records that recognize an operating expense on the document date without changing cash. Partial/full settlements create linked `payable-settlement` cash movements and atomically update the payable balance; settlements do not add a second expense.
- Added explicit customer receivable records (not quotations/invoices generated automatically), with original/settled/outstanding totals. Partial/full `receivable-settlement` movements update cash and receivable balance atomically without counting revenue twice.
- Added additive IndexedDB v4 stores `categories`, `suppliers`, `payables`, and `receivables` with `{id}` keys and no indexes. Existing stores and key paths are unchanged. Settlement uses a single read-write transaction across the document, account, and transaction stores, checking current outstanding balance and same-currency active account before writing.
- Updated backup export to schema version 4 and added all four new stores to the same read-only snapshot transaction. Restore remains disabled. Service-worker shell cache version advanced to v14; no new runtime dependency was added.
- No comprehensive browser test was run. Real IndexedDB migration, settlement interaction, concurrent-tab behavior, offline behavior, and iOS Safari remain unverified. Categories are built-in plus user-managed local entries; settlement corrections/reversals remain future work.
- Added accounting period reports with currency-separated recognized income/expenses/profit, owner withdrawals, cash receipts/payments, open receivable/payable amounts, and opening/current cash/bank balances. Added per-customer and per-supplier statements with document and settlement event timelines and period opening/closing outstanding amounts calculated from linked settlement records. Added project financial summaries separating estimates and linked quotes from linked actual transactions/documents; project actual totals are explicitly marked partial.
- Reports reuse existing version-4 stores and do not add a database migration or alter records. Backup store list is unchanged. The service-worker cache version advanced to v15 because the shell script changed. Source/syntax checks only; no browser, live IndexedDB, offline, or historical-record verification was performed.
- Supplier payables and customer receivables are intentionally not editable/deletable after creation, and posted settlement movements cannot be edited/deleted from the generic transaction list. A future correction/reversal workflow is needed before allowing changes that could alter recognized activity or outstanding balances.
- JavaScript syntax checks passed for all app scripts and the service worker. Mocked financial calculations covered account balances, each transaction type, period filtering, editing/deletion recalculation, invalid/non-finite/overflow values, and dates. Source-level checks covered additive migration and quotation PDF cost/profit exclusion; HTML/RTL/ID/local-reference, manifest JSON, and service-worker asset checks passed. Actual browser interaction, real database migration, offline execution, PDF rendering, and iOS Safari remain unverified.
- Added customer-to-quotation review using the persisted `clientId`, and optional project-to-customer linking carried into the quotation editor. Quotes created from saved projects retain an optional `sourceProjectId` for project-specific review. Existing quotes retain their customer/item/price/tax snapshots; changing the selected customer's master record does not rewrite a quote.
- New manually entered customer records and their quotation are written together in one IndexedDB transaction. Editing a quote linked to an existing customer no longer updates that customer's master record implicitly.
- Existing quotation discount, tax, currency, line-item snapshots, payments, warranty fields, and creation timestamp are retained when editing and saving.
